## 5. MAIN PROJECT: GABARIT VISION IA

### Project overview

Gabarit Vision IA, also referred to as Gabarit-vision-IA, is a computer-vision project designed to automate conformity checking for industrial pattern or template layouts.

The project is associated with my GitHub username, Adnane-coder.

The underlying problem is that checking industrial patterns manually can require time and careful visual inspection. The project aims to support this process by comparing visual information against references and identifying potential conformity issues.

### Intended workflow

The project works toward a pipeline that connects reference documents, image processing, AI-based segmentation, conformity checks, and a dashboard.

The project context includes PDF reference material associated with 1:1 Gerber AccuMark patterns and an approximate tolerance of plus or minus three centimetres.

The intended checks include identifying missing pieces and unexpected pieces and producing a structured conformity result.

The application is designed around a React frontend and a FastAPI backend.

Canny edge detection was considered or used as an image-processing baseline, while U-Net segmentation was introduced as an alternative for identifying pattern shapes.

The development context mentions four traces and 125 annotated pieces. These figures describe the project context and should not be treated as proof that the system generalizes to every industrial pattern.

The repository configuration has included MOCK_MODE=true and AI_ENABLED=false as default settings. This distinction is important: a mock demonstration can show the application workflow without proving that live AI inference is enabled. The project has also had a real-mode configuration context in which four out of four checkpoints were described as satisfied.

### What the project demonstrates

This project demonstrates my interest in connecting several technical components into a coherent application.

It involves understanding an industrial problem, handling visual or document-based inputs, exploring computer-vision methods, comparing alternatives, building an API, and integrating the workflow into a user interface.

The project is relevant to computer vision, applied machine learning, AI engineering, backend development, and full-stack AI application development.

I have been exploring how to build a small but genuine Retrieval-Augmented Generation API using FastAPI, with a target development time of approximately four to six hours for an initial portfolio version.

My objective is to understand the full process rather than simply follow a tutorial without understanding it.

A basic RAG application typically involves:

1. Loading a collection of documents.
2. Splitting the documents into manageable chunks.
3. Generating embeddings for those chunks.
4. Indexing the embeddings in a vector store or another retrieval mechanism.
5. Retrieving relevant passages in response to a question.
6. Passing the retrieved context to a language model.
7. Generating an answer grounded in the available documents.
8. Exposing the workflow through an API such as FastAPI.
9. Testing whether the retrieved passages actually support the generated answer.

I want this kind of project to be small enough to complete but strong enough to demonstrate real understanding. Useful portfolio evidence would include a clear README, setup instructions, example questions, a working endpoint, and honest discussion of limitations.

I am also interested in agentic AI. However, I understand that a basic RAG application is not automatically an agentic AI system.
